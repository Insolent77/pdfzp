# Мой Ломоносов — Генератор актов преподавателей

Рабочий сайт: **https://insolent77.github.io/pdfzp/**.

Приложение работает непосредственно на GitHub Pages. Собственный сервер, PostgreSQL, Docker и ключ шифрования не нужны. Расчёты, заполнение DOCX и создание PDF выполняются в браузере. Справочник, версии, шаблоны и история сохраняются на устройстве в IndexedDB; исходные таблицы и копии PDF находятся в Google.

## Первый запуск

1. Откройте **Настройки**. Подключите Google по инструкции ниже либо добавьте преподавателя вручную и загрузите XLSX/CSV в разделе **Расчёты**.
2. Проверьте в карточке преподавателя ФИО, дательный падеж, договор, задание, даты, реквизиты, ссылки, ставки с периодами и правила начислений. Недостающие сведения автоматически не выдумываются.
3. В настройках заполните заказчика, импортируйте оригинальный DOCX из Drive или с устройства и подтвердите конкретную проверенную версию шаблона. Для ИП нужен отдельный согласованный шаблон.
4. Выберите преподавателя и период. Обновите расчёт из Google либо загрузите XLSX/CSV. Проверьте детализацию и сверку. Ручные корректировки требуют основания.
5. Укажите номер акта по вашему регламенту, дату и юридические подтверждения. Создайте PDF либо явно отмеченный черновик.
6. Скачайте PDF и DOCX из **Истории актов**. Если подключён Google, включено автокопирование и указана папка, PDF автоматически сохраняется также в Google Drive.

## Google OAuth Client ID — настройка один раз

Для чтения закрытых таблиц Google требует вашего согласия. Браузерному сайту нужен публичный OAuth Client ID:

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект.
2. В **APIs & Services → Library** включите **Google Sheets API** и **Google Drive API**.
3. В **Google Auth Platform** заполните название приложения, контактную почту и аудиторию. Для личного использования выберите External / Testing и добавьте свою почту в Test users.
4. В **Clients** создайте OAuth client типа **Web application**.
5. В **Authorized JavaScript origins** добавьте `https://insolent77.github.io` — без `/pdfzp/`. Redirect URI для используемого popup token flow не нужен.
6. Скопируйте Client ID вида `…apps.googleusercontent.com`, вставьте в поле **Google OAuth Client ID** на сайте и сохраните настройки.
7. Нажмите **Подключить Google-аккаунт**. Выберите аккаунт с доступом к расчётным таблицам, шаблону и папкам преподавателей. Разрешите всплывающие окна для сайта.

**Client Secret и сервисные ключи на сайт не вводятся.** Используется [Google Identity Services token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model). Короткоживущий access token находится только в памяти вкладки; в GitHub и резервные копии он не записывается. После обновления страницы или истечения доступа Google нужно подключить повторно. Сохранённая история остаётся.

Scopes: Sheets readonly, Drive для чтения существующих DOCX и записи PDF в существующие папки, openid/email. При использовании за пределами личных тестовых аккаунтов Google может потребовать проверку scopes. Права доступа к Google-файлам проверяет Google.

## Источники и сверка

Ссылки и ID источников меняются в настройках без редактирования кода.

- **Лист «Данные для актов»** — договорные поля, ссылки и контрольные итоги. Синхронизация переносит преподавателей в локальную базу. Подтверждённые и изменённые вручную поля не перезаписываются, конфликты фиксируются в журнале.
- **Персональная зарплатная таблица** — подробные строки для расчёта и реестра. Месячная вкладка выбирается как `MM.YY`, например `10.26`.
- **XLSX/CSV** — полноценный режим без Google. В XLSX выбирается месячный либо единственный лист. CSV поддерживает UTF-8, `;`/`,` и десятичную запятую. Формулы XLSX должны быть пересчитаны и сохранены в исходной программе.

Общая ячейка месяца `B2` сводного листа не переключается автоматически. При отличии периода сводки от выбранного расчёт берётся из персональной месячной вкладки, а приложение показывает предупреждение. Если месяцы совпали, итог сводки сравнивается с подробным источником. Исходные строки и сводка сохраняются в версии расчёта со временем загрузки.

Фактические начисления с коэффициентами не умножаются повторно на ставку. Денежные расчёты используют decimal.js и HALF_UP до копейки. Признаки проведения `0.5`, `0.25` и другие требуют явных правил; неизвестные операции блокируют финальный акт. Компенсации не увеличивают количество проведённых занятий.

В JSON-настройках карточки индексы строк и колонок начинаются с нуля. Для плоского файла задайте контрольный итог источника в mapping:

```json
{"headerRow":0,"date":0,"student":1,"minutes":2,"flag":3,"amount":4,"total":"1200.50"}
```

Пример правил (применимость нужно подтвердить по договору):

```json
{"unitMinutes":60,"approved":false,"flags":{"0.5":{"type":"COMPENSATION","unitsFactor":"0","requiresBasis":true},"0.25":{"type":"COMPENSATION","unitsFactor":"0","requiresBasis":true}},"identifiers":[{"pattern":"^TEAM-","type":"GROUP"}],"extraPatterns":[{"pattern":"бонус|вознаграждение","type":"BONUS"}]}
```

Ставки хранятся с периодами действия, видом услуги, форматом, длительностью единицы и подтверждением. Они определяют расчётные единицы и базовую ставку акта, сохраняя фактическую сумму выплаты. После изменения условий нужен новый расчёт.

## DOCX, PDF и история

Оригинальный юридический DOCX загружается из Google Drive или с устройства и не публикуется в репозитории. Общий адаптер заполняет поля фактического шаблона и добавляет реестр той же версии расчёта. Юридические пункты сохраняются; сведения о НПД, претензиях, интеллектуальных результатах и нумерации требуют подтверждения.

PDF формируется в браузере с кириллическим шрифтом и переносами таблиц. Это браузерная вёрстка содержимого заполненного DOCX, а не LibreOffice: расположение строк и страниц может отличаться от Word. Перед передачей исполнителю просмотрите PDF. Заполненный DOCX также доступен для скачивания.

Поддерживаются маркеры исходной формы: `[НОМЕР АКТА]`, `[НОМЕР ДОГОВОРА]`, `[ДАТА ДОГОВОРА]`, `[НОМЕР ЗАДАНИЯ]`, `[ДАТА ЗАДАНИЯ]`, ФИО, период, источник и суммы. Изменение структуры юридического шаблона может потребовать отдельного адаптера. Финальный ИП-акт с положением о чеке НПД блокируется.

Повторное создание за период требует явного подтверждения новой версии с сохранением номера акта. История содержит суммы, версии, подтверждения, снимок расчёта и контрольную сумму шаблона. Черновик нельзя сделать финальным сменой статуса: PDF нужно пересоздать. При ошибке Drive локальный PDF сохраняется; повторная загрузка доступна из истории.

## Где хранятся данные

| Место | Содержимое |
| --- | --- |
| GitHub | Код, статическая сборка и синтетические тесты |
| Этот браузер | Карточки, расчёты, шаблоны, PDF/DOCX и журнал в IndexedDB |
| Google | Исходные таблицы, папки и сохранённые копии PDF |

В настройках доступны **Скачать резервную копию** и **Восстановить данные этого браузера из копии**. Копия включает документы и шаблоны; восстановление заменяет текущую локальную рабочую область. Данные разных компьютеров сами не объединяются. Очистка данных сайта удаляет локальные записи, поэтому сохраняйте резервные копии и PDF в Drive.

Статический сайт публично открывается; локальная рабочая область доступна пользователю устройства. Серверных доверенных ролей администратора, общей базы и общего журнала организации здесь нет. Доступ к закрытым Google-файлам контролирует Google. Условия обработки персональных данных и использования Google определяет оператор; код не является подтверждением соответствия законодательству.

## Публикация и разработка

Push в `main` запускает **Deploy GitHub Pages**: публикуется `dist` с базовым путём `/pdfzp/`. Переменные окружения для запуска сайта не нужны. В настройках Pages используйте Source → GitHub Actions.

```sh
npm ci
npm run dev
npm run build:pages
npm test
```

Для локального входа Google можно добавить `http://127.0.0.1:5173` в Authorized JavaScript origins своего OAuth client.

Тесты включают сценарий CSV → IndexedDB → DOCX → настоящий PDF → новая версия → резервная копия и восстановление. Контрольные октябрьские суммы используются только в синтетических тестах: 104/32 единицы, 150 068/62 120 ₽, 4 600 ₽ доплат, 1 080 ₽ компенсаций, 217 868 ₽ итого. Фиксированной зарплаты преподавателя в рабочем коде нет.

Старый серверный код оставлен для совместимости и регрессионных тестов. Сайт его не использует и не обращается к `/api`. Историческая документация — [docs/server-legacy.md](docs/server-legacy.md).
