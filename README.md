# Мой Ломоносов — Генератор актов преподавателей

Самостоятельное закрытое приложение: React + TypeScript, Express, PostgreSQL 17, Prisma 6, серверные сессии PostgreSQL и серверная обработка DOCX → PDF через LibreOffice/Gotenberg. Google Sheets — внешний источник, а расчёты, версии, справочник и журнал документов хранятся в собственной БД. Интерфейс использует обычный CSS без внешних CDN и шрифтов. Это позволяет работать в закрытом контуре без запросов браузера к Google.

## Запуск на сервере

Нужен Linux-сервер с Docker Compose, диском с шифрованием, резервным хранилищем и доменом. Для реальных персональных данных инфраструктуру и правовые основания обработки выбирает оператор. Код сам по себе не означает соответствие законодательству.

```sh
git clone https://github.com/Insolent77/pdfzp.git
cd pdfzp
cp .env.example .env
# Заполнить .env; значения ниже генерировать независимо
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
docker compose up -d --build
```

В `.env` задайте:

| Переменная | Назначение |
| --- | --- |
| `POSTGRES_PASSWORD` | Уникальный пароль PostgreSQL |
| `DATABASE_URL` | `postgresql://acts:<URL-encoded password>@db:5432/acts` |
| `SESSION_SECRET` | Случайная строка от 32 символов |
| `TOKEN_ENCRYPTION_KEY` | 32 случайных байта как 64 hex-символа; хранить отдельную резервную копию |
| `BOOTSTRAP_EMAIL`, `BOOTSTRAP_PASSWORD` | Первый администратор, пароль от 14 символов |
| `APP_URL` | Точный адрес приложения; production требует HTTPS |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Серверный OAuth Google |
| `GOOGLE_REDIRECT_URI` | `<APP_URL>/api/google/callback` |
| `DIRECTORY_SPREADSHEET_ID` | ID справочника преподавателей |
| `TEMPLATE_DRIVE_ID` | ID исходного DOCX-шаблона |
| `GOTENBERG_URL` | `http://converter:3000` внутри Compose |

Службы БД и конвертера не публикуют порты. Приложение по умолчанию доступно только на `127.0.0.1:3000` хоста. Для production укажите `DOMAIN` в `.env`, направьте DNS на сервер и запустите:

```sh
docker compose -f compose.yaml -f compose.production.yaml up -d --build
```

Caddy выдаёт TLS-сертификат. Разрешите на firewall только необходимые SSH и 80/443. Не открывайте наружу PostgreSQL или Gotenberg. Миграции и создание первого администратора выполняются при старте контейнера. Существующий пароль bootstrap никогда не перезаписывается.

## Подключение Google

1. Создать OAuth Web application в Google Cloud Console, включить Sheets API, Drive API, настроить экран согласия и разрешённые тестовые аккаунты/верификацию приложения.
2. Зарегистрировать точный redirect URI; заполнить серверные переменные и перезапустить приложение.
3. Войти администратором → Настройки → Подключить Google-аккаунт. Используются state, PKCE и offline access. Refresh/access tokens шифруются AES-256-GCM в PostgreSQL, клиент их не получает.
4. Подключать аккаунт с доступом к действующему справочнику, зарплатным таблицам и папкам преподавателей. Sheets scope — readonly; Drive scope нужен для чтения существующих DOCX и записи в существующие папки, поэтому он шире `drive.file`. Заявка Google может потребовать проверки scopes.
5. Если справочник БД пуст, первый OAuth callback автоматически импортирует лист «Преподаватели». Повторная синхронизация доступна отдельной кнопкой.
6. Синхронизация не подтверждает реквизиты и не переносит ставки ноября на октябрь. Номер договора используется для первоначального определения СМЗ/ИП, а окончательное подтверждение типа остаётся за администратором.
7. Изменённые вручную поля защищены от перезаписи. У подтверждённой карточки защищены все сведения. Конфликты старых/новых значений фиксируются в журнале; автоматического разрешения конфликтов нет. Пустые значения источника не стирают заполненные поля БД. Неоднозначные ФИО в справочнике следует устранить до синхронизации.

Проблемы доступов, отозванный OAuth и отсутствующий месячный лист возвращаются пользователю как ошибки. Обновление расчёта не подменяет старую версию: каждая успешная загрузка сохраняется отдельно.

## Первый расчёт и акт

1. В карточке преподавателя проверить ФИО, дательный падеж, тип исполнителя, реквизиты, договор и задание, их даты, ссылки на таблицу и папку. Даты хранятся в ISO `YYYY-MM-DD`.
2. Сохранить условия тарифа и период его действия. Настроить правила проведения и классификации, затем отдельно подтвердить их по договору.
3. Выбрать месяц и год. Кнопка «Обновить расчёт» делает настоящий запрос Sheets API к соответствующему листу `MM.YY`; переключение параметров загружает сохранённые версии из БД.
4. При отсутствии Google можно загрузить XLSX/CSV в разделе «Расчёты». Для XLSX выбирается месячный лист либо единственный лист файла. CSV поддерживает UTF-8, `;`/`,` и десятичную запятую. Значения формул XLSX должны быть пересчитаны в исходной программе: сервер читает сохранённые результаты, а не выполняет Excel-формулы.
5. Сверить детализацию, контрольный итог, компенсации, бонусы, штрафы и корректировки. Ручные корректировки требуют основания, автора и создают новую версию расчёта, сохраняя контроль исходной суммы.
6. Настройки → Шаблоны: импортировать шаблон из Drive либо загрузить оригинальный DOCX вручную. Юридические документы с реквизитами не публикуются в репозитории; сервер хранит их в закрытом томе. Обязательно проверить конкретную контрольную сумму и подтвердить юридическую форму.
7. Внести реквизиты заказчика. Для автоматической копии PDF в Drive включить настройку и подтвердить основания передачи данных. После этого каждый успешно созданный PDF автоматически загружается в папку выбранного преподавателя. Ошибка Drive сохраняется в истории; локальный PDF остаётся доступен, повторная загрузка выполняется кнопкой.
8. Указать номер и основание согласованной нумерации, дату акта, точную формулировку о претензиях, результаты интеллектуальной деятельности и подтверждения условий/НПД. Номер не назначается автоматически.
9. Нажать «Проверить», устранить ошибки и сформировать финальный PDF. При ошибках доступен только явно отмеченный черновик. Без шаблона или конвертера даже черновик не имитируется.
10. PDF содержит акт и реестр той же версии расчёта. История сохраняет DOCX, PDF, номер, дату, суммы, исходные сведения, подтверждения, контрольную сумму шаблона и журнал статусов.

Повторный выпуск за период требует явного согласия на новую версию. Номер прежнего акта сохраняется. Старая версия остаётся в журнале, заменять её файл нельзя. Черновик нельзя сделать подписанным сменой статуса: нужно сформировать финальный документ.

## Правила начислений и mapping

Суммы хранятся строками в десятичном формате и рассчитываются `decimal.js`; денежное округление — до двух знаков HALF_UP. Фактические выплаты источника используются напрямую и повторно не умножаются на коэффициенты. Расчётные единицы выводятся из длительности и условий тарифа; компенсации не увеличивают число проведённых занятий.

Старый многострочный формат зарплатных таблиц распознаётся по заголовкам «Проведено» и «Итог за месяц». Учитываются блоки «Общая Выплата за Ученика», реальные выплаты строк, итоги бонусов/штрафов. Для плоских таблиц заголовки распознаются автоматически. Непонятные операции остаются `UNKNOWN` и блокируют финальный документ.

Пример JSON правил в карточке (это пример конфигурации; подтвердите применимость по договору):

```json
{
  "unitMinutes": 60,
  "approved": false,
  "flags": {
    "0.5": {"type": "COMPENSATION", "unitsFactor": "0", "requiresBasis": true},
    "0.25": {"type": "COMPENSATION", "unitsFactor": "0", "requiresBasis": true}
  },
  "identifiers": [
    {"pattern": "^TEAM-", "type": "GROUP"},
    {"pattern": "^PERSON-", "type": "INDIVIDUAL"}
  ],
  "extraPatterns": [{"pattern": "бонус|вознаграждение", "type": "BONUS"}]
}
```

Значения `0.5`, `0.25` не имеют глобально заданного финансового значения. Они работают только после настройки соответствующего правила. `1` означает проведённое занятие, но его вид всё равно должен распознаваться. Поддерживаются явные `INDIVIDUAL`, `GROUP`, `BONUS`, `COMPENSATION`, `CORRECTION`, `FINE` в колонке типа выплаты.

В `mapping` индексы строк и колонок начинаются с нуля. Пример для плоского файла:

```json
{"headerRow":0,"startRow":1,"date":0,"student":1,"service":2,"format":3,"minutes":4,"flag":5,"amount":6,"basis":7,"type":8,"total":"12345.67"}
```

Для flat XLSX/CSV задайте контрольный `total` из источника в mapping. Для Google-формата итог берётся из месячной вкладки. Отсутствующий итог блокирует финальный акт. Встроенный адаптер читает A:AZ и до 20 000 строк; более широкие/сложные структуры требуют расширения адаптера, а не произвольного угадывания.

Договорные ставки сохраняются отдельно с датами действия, услугой, форматом, величиной расчётной единицы и подтверждением. Если такая ставка найдена для даты занятия, она определяет длительность единицы и отображаемую базовую ставку, но не заменяет фактическую выплату. Пересекающиеся совпадения тарифов дают ошибку.

## Юридический шаблон

Адаптер работает с реальным DOCX, сохраняет документ, стили, подписи, шапки и юридические пункты; заполняет исходные поля, заменяет таблицу начислений и добавляет реестр. Текст неизменённых абзацев остаётся исходным. Изменяемые поля и подтверждения сохраняются в snapshot документа.

Для ИП нужно подключить отдельный согласованный DOCX. Приложение не удаляет НПД-положения из шаблона самозанятого самостоятельно. Финальный ИП-акт с положением о чеке НПД блокируется. Отдельный шаблон должен сохранять поддерживаемую структуру и маркеры: `[НОМЕР АКТА]`, `[НОМЕР ДОГОВОРА]`, `[ДАТА ДОГОВОРА]`, `[НОМЕР ЗАДАНИЯ]`, `[ДАТА ЗАДАНИЯ]`, поля ФИО и сумм исходной формы. Если структура отличается, нужен отдельный адаптер и повторная юридическая/визуальная проверка. Произвольный DOCX не считается автоматически совместимым.

Статус «Готов к подписанию» означает прохождение программных проверок и подтверждения администратора, а не заключение юриста или электронную подпись. Согласование нумерации, условий НПД, замечаний и интеллектуальных прав выполняет уполномоченный человек. Реквизиты никогда не заполняются по аналогии с другими преподавателями.

## Безопасность и эксплуатация

- Сессии хранятся в PostgreSQL, cookie HttpOnly/SameSite=Lax, production Secure. Вход ограничен rate limit, пароли bcrypt, изменяющие запросы требуют CSRF и допустимый Origin.
- ADMIN изменяет справочник, настройки, расчёты, пользователей и документы. EMPLOYEE просматривает расчёты и скачивает документы. Изменение ролей/блокировка проверяются на каждом запросе; отключённый пользователь теряет доступ и к существующей сессии.
- Все API закрыты авторизацией, кроме health/session/login. Файлы не находятся в public/static. Скачивание требует сессии и журналируется.
- OAuth секреты находятся только в окружении сервера, токены в БД шифруются AES-GCM. БД, файлы и резервные копии требуют инфраструктурного шифрования, контроля доступа, ротации и мониторинга. Утрата `TOKEN_ENCRYPTION_KEY` делает сохранённые токены недоступными.
- Импорт ограничен по размеру и числу строк, данные не исполняются как формулы/скрипты. В БД сохраняются исходные строки и время загрузки. SQL выполняется через Prisma с параметрами.
- Рабочие персональные данные, `.env`, runtime storage и исходные приватные выгрузки исключены из Git. В тестовом файле контрольного сценария используются только синтетические строки без имён, внешних ссылок и реквизитов.
- Для данных граждан РФ предусмотрите основную БД, файловое и резервное хранилище в РФ; определите цели, основания, сроки хранения и удаления, уведомления, организационные меры и порядок реагирования. Использование Google и трансграничная передача требуют отдельной оценки оператором. Проверить актуальные требования перед вводом системы в эксплуатацию: [Роскомнадзор](https://rkn.gov.ru/personal-data/), [разъяснение РКН о локализации](https://storage.yandexcloud.net/comply-publicfiles/public/Otvet_RKN_24.03.2025_lokalizatsija.pdf).

Приложение не удаляет подписанные документы и историю автоматически. Политику сроков хранения и процедуру удаления определяет оператор, с учётом договорных и учётных обязательств. Размещение на зарубежном сервере без оценки требований не предусмотрено как готовая схема соответствия.

## Резервирование и восстановление

```sh
BACKUP_DIR=/mnt/encrypted-backups/acts sh scripts/backup.sh
# Запланировать на сервере ежедневно; проверить тестовое восстановление.
```

Скрипт создаёт `database.dump` и `documents.tar.gz` с правами только владельцу. Секрет AES, OAuth client secret и SESSION_SECRET резервировать отдельно в менеджере секретов. Копии содержат персональные данные: шифруйте носитель, ограничьте доступ и настройте срок хранения.

Восстановление в **новое изолированное окружение**, без работающего приложения:

```sh
docker compose up -d db
docker compose exec -T db pg_restore -U acts -d acts --clean --if-exists < /backup/database.dump
# Восстановите documents.tar.gz в том /app/storage контейнера приложения,
# затем верните прежний TOKEN_ENCRYPTION_KEY и остальные серверные секреты.
docker compose up -d
```

Не запускайте restore поверх рабочей БД. Проверьте вход, скачивание ранее созданного PDF и расшифровку Google-аккаунта после тестового восстановления.

## Разработка и проверки

```sh
npm ci
npx prisma generate
npm run db:migrate
npm run bootstrap
npm run dev
# Во втором терминале для UI:
npx vite --host 127.0.0.1
npm run build
npm test
```

`npm test` запускает реальные HTTP-запросы Express с Prisma и одноразовым embedded PostgreSQL (PGlite, только тесты). Рабочий сервер всегда использует PostgreSQL по `DATABASE_URL`. Тесты проверяют login/CSRF/роли, импорт CSV, сохранение расчёта и новой версии, ручной бонус, конфликт правки, запрет неподтверждённого акта, денежную сверку, неизвестные признаки проведения и правовые подтверждения.

Контрольный октябрьский пример находится только в тестах: 104/32 единицы, 150 068/62 120 ₽, 4 600 ₽ доплат, 1 080 ₽ компенсаций, 216 788 ₽ услуг, 217 868 ₽ итого. Боевой код этих сумм или преподавательского оклада не содержит.

Публичные DOCX-тесты используют синтетическую структурную фикстуру без персональных и договорных данных. Для локальной проверки юридического оригинала задайте ACT_TEMPLATE_PATH с путём к закрытому файлу. Конверсионный тест делает настоящий HTTP-запрос Gotenberg, если задан `GOTENBERG_URL`; без конвертера он явно пропускается. GitHub Actions поднимает Gotenberg и запускает его вместе с остальными проверками, сборкой и аудитом зависимостей.

Перед передачей акта исполнителю оператор обязан просмотреть PDF после конвертации: корректность переноса длинных таблиц, шрифты, подписи и юридическое содержание. Автоматические проверки XML и `%PDF-` не заменяют визуальную проверку каждой разновидности шаблона.

## Что не подключается автоматически кодом

Репозиторий не содержит рабочих OAuth credentials, домена, доступа к серверу, подтверждённых реквизитов и юридических согласований. Поэтому наличие кода и успешных тестов не означает, что производственный сайт уже развёрнут или что Google-источники доступны приложению. Выполните описанную настройку, импорт и контроль первого документа; не используйте заполненный пример в качестве подтверждения договора или ставки.
